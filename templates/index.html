Security & System Architecture

Security & Cryptography

Client-side encryption model, key transport and integrity verification.

Core principle: Encryption keys are never uploaded to the server. They are carried in the share link's URL fragment and shared with the recipient.

01 Browser Encryption

Cipher
AES-256-GCM (256-bit key)
Nonce
Fresh 96-bit unique IV per file
Integrity
128-bit authentication tag + AAD
AAD binding
Share ID + File ID + Filename + Size

All encryption executes locally in-browser via the Web Crypto API. Cryptographic Additional Authenticated Data (AAD) prevents cross-file and cross-collection ciphertext substitution.

02 Key Transport & Privacy

Key transport
URL fragment (#) only
Server visibility
Opaque ciphertext only
Plaintext
Never uploaded or transmitted
Protocol
Version 1 (v1) schema

Browsers never transmit the URL fragment to the server in HTTP requests. Decryption keys are held in memory by the sender and recipient only.

Storage & Ephemeral Architecture

Storage & Retention Policy

Server persistence, transfer limits and ephemeral lifecycle.

Ephemeral storage notice: Files are stored temporarily on the server's ephemeral filesystem and may become unavailable after restart, redeployment or instance replacement. No retention guarantee is provided.

01 Storage Parameters & Limits

Storage model
Ephemeral server filesystem
Retention
Temporary (no persistence guarantee)
File limits
25 MB per file · 50 MB per transfer
Collection cap
Max 10 files per transfer

Recipients should download and decrypt files promptly. The server does not maintain long-term archival copies or backup snapshots of uploaded ciphertext collections.
